# ملخص شامل - رحلة التعلم والمشاريع

---

## الجزء الأول: نشر مشروع TaskFlow على Render (تعلمناه)

### ✅ خطوات النشر الكاملة

1. **تجهيز الكود قبل الرفع**
   - تأكد من سطر `start` صحيح بـ `package.json`: `"start": "node src/app.js"`
   - البورت ماخوذ من البيئة: `const PORT = process.env.PORT || 3000;`
   - `.env` مذكور بـ `.gitignore`

2. **إنشاء حساب على Render** (عن طريق GitHub)

3. **إنشاء قاعدة بيانات PostgreSQL على Render**
   - New → PostgreSQL → اسم + Region + Plan Free
   - نسخ **Internal Database URL**

4. **إنشاء Web Service للباك إند**
   - Build Command: `npm install && npx prisma generate && npx prisma migrate deploy`
   - Start Command: `npm start`
   - Instance Type: Free

5. **إضافة Environment Variables**
   - `DATABASE_URL` = Internal Database URL
   - باقي المتغيرات (JWT_SECRET، إلخ) - بدون `PORT` وبدون `DB_HOST/PORT/USER/PASSWORD/NAME`
   - `NODE_ENV=production`

6. **مراقبة الـ Logs لحد ما تصير الحالة "Live"**

### 📌 دروس ومشاكل واجهناها (مهم تتذكرها)

| المشكلة | السبب | الحل |
|---|---|---|
| `Application exited early` | سطر `start` بيشاور على ملف غير موجود | تصحيح المسار بـ `package.json` |
| بيانات قديمة مش موجودة على Render | القاعدة المحلية والقاعدة على Render **منفصلتين تماماً** | لازم نقل يدوي إذا بدنا البيانات |
| فشل الاتصال بـ pgAdmin/Prisma Studio من الجهاز (`timeout`) | الشبكة/الراوتر عم يحظر بورت 5432 | جرب شبكة تانية (Hotspot) |
| Shell مو متوفر على الخطة المجانية | قيود Render | استخدام pgAdmin بدل الـ Shell |

### 📌 ملاحظات دائمة لازم تحفظها

- الباك إند المجاني بينام بعد 15 دقيقة عدم استخدام (أول طلب بياخد ~30-60 ثانية)
- قاعدة البيانات المجانية إلها تاريخ انتهاء (~شهر)، تحتاج تجديد
- Internal URL بين خدمات Render، External URL للاتصال من جهازك
- Auto-Deploy: أي `git push` عالـ main بيعمل نشر جديد تلقائياً

## الجزء الثاني: مشروع BarberOnYourTime (المشروع الجديد)

### 🎯 فكرة المشروع
تطبيق حجز مواعيد لصالونات الحلاقة، بنظام "تحويل تلقائي" - لو حلاق رفض الطلب، بينتقل تلقائياً لحلاق تاني متوفر بنفس الوقت.

### 👥 أنواع المستخدمين
- **Owner (صاحب المحل)**: يضيف حلاقين، يحدد خدمات، يشوف كل الحجوزات، يتدخل لو كل الحلاقين رفضوا
- **Staff (حلاق)**: يحدد جدول دوامه، يشوف حجوزاته، يقبل/يرفض
- **Customer (عميل)**: يحجز خدمة مع حلاق معين بوقت محدد

### 🔄 دورة حياة الحجز
1. العميل يختار: خدمة + حلاق معين + وقت → الحالة: **PENDING**
2. الحلاق يوافق → **CONFIRMED** + إشعار للعميل
3. الحلاق يرفض → ينتقل تلقائياً لأقرب حلاق متوفر بنفس الوقت
4. لو كل الحلاقين رفضوا → **NEEDS_OWNER** + إشعار لصاحب المحل

### 🗄️ الجداول (Database Schema) - ✅ مكتملة

1. **User**: id, name, email, password, role (OWNER/STAFF/CUSTOMER)
2. **Business**: id, name, address, ownerId
3. **Staff**: id, userId, businessId
4. **Service**: id, name, durationMinutes, price, businessId
5. **Booking**: id, startTime, status, customerId, serviceId, staffId
6. **BookingAttempt**: id, order, status, bookingId, staffId
7. **Availability**: id, dayOfWeek, startTime, endTime, staffId

## 📝 ملاحظات تقنية مهمة تتذكرها

- **نمط الكود المتبع**: Controller خفيف (يتحقق البيانات الأساسية بس) → Service (فيه كل منطق العمل الحقيقي مع Prisma)
- **الأخطاء**: نستخدم `throw new ApiError(statusCode, message)` بدل `res.status().json()` مباشرة
- **كل Controller ملفوف بـ `asyncHandler`** حتى نتجنب تكرار try/catch
- **الردود الناجحة**: عن طريق `successHandler(res, statusCode, message, data)`
- **JWT**: `expiresIn: "7d"`, بيحمل `{ userId, role }`
- **حماية Routes**: نستخدم `protect` middleware قبل الـ Controller مباشرة بالـ Route
- ⚠️ **لا تحدّث Prisma لنسخة 8 (rc)** - لسا تجريبية وغير مستقرة، خليك على `7.9.1`

## الجزء الثاني: مشروع BarberOnYourTime (المشروع الجديد)

### 🎯 فكرة المشروع
تطبيق حجز مواعيد لصالونات الحلاقة، بنظام "تحويل تلقائي" - لو حلاق رفض الطلب، بينتقل تلقائياً لحلاق تاني متوفر بنفس الوقت.

### 👥 أنواع المستخدمين
- **Owner (صاحب المحل)**: يضيف حلاقين، يحدد خدمات، يشوف كل الحجوزات، يتدخل لو كل الحلاقين رفضوا
- **Staff (حلاق)**: يحدد جدول دوامه، يشوف حجوزاته، يقبل/يرفض
- **Customer (عميل)**: يحجز خدمة مع حلاق معين بوقت محدد

### 🔄 دورة حياة الحجز
1. العميل يختار: خدمة + حلاق معين + وقت → الحالة: **PENDING**
2. الحلاق يوافق → **CONFIRMED** + إشعار للعميل
3. الحلاق يرفض → ينتقل تلقائياً لأقرب حلاق متوفر بنفس الوقت
4. لو كل الحلاقين رفضوا → **NEEDS_OWNER** + إشعار لصاحب المحل

### 🗄️ الجداول (Database Schema) - ✅ مكتملة

1. **User**: id, name, email, password, role (OWNER/STAFF/CUSTOMER)
2. **Business**: id, name, address, ownerId
3. **Staff**: id, userId, businessId
4. **Service**: id, name, durationMinutes, price, businessId
5. **Booking**: id, startTime, status, customerId, serviceId, staffId
6. **BookingAttempt**: id, order, status, bookingId, staffId
7. **Availability**: id, dayOfWeek, startTime, endTime, staffId
